## Project Overview

A branded Streamlit dashboard covering enrollment, academic performance, course-level
offerings, admissions, and finance/operations for a university, 2015–2025.

**This is the warm-up project of the capstone series.** Its purpose is breadth: exercise
dashboard layout, cross-tab filter state, drill-down, and branding. The three sibling
projects that follow take the opposite approach — one sharp question each, on real IPEDS
data.

---

## Critical Constraint — Read Before Writing Any Code

**All data in this project is synthetic.** It is generated by `generate_data.py` and
describes no real institution.

This is the **only** project in the series where synthetic data is permitted — the other
three have a hard no-synthetic-data rule. Do not carry this project's approach into them,
and do not carry their rule into here.

Because the data is fake:

- **Never present a figure from this dashboard as a fact about Yeshiva University** or any
  real school, in the UI, the README, or a commit message.
- The README's "Scope — read this first" section states this plainly. Keep it there.
- The in-app footer notes the data is synthetic. Do not remove it.

The dashboard is YU-*branded* (navy/gold). Branding is not a claim about data provenance,
but it does make the synthetic-data disclaimer load-bearing. Keep the disclaimer visible.

## Stack

- **App framework:** Streamlit
- **Language:** Python
- **Data:** Flat CSVs generated locally — no database, no backend, no API
- **Charting:** Streamlit native chart elements + Plotly where more control is needed
- **Data handling:** pandas

Do not introduce new libraries without asking first.
Do not add a database — the flat-CSV approach is deliberate for this project.

## Data

### Generation

`generate_data.py` is **deterministic** — `SEED = 42`, via `np.random.default_rng(SEED)`.
The same run produces the same data every time, so the dashboard is stable across restarts
and screenshots stay reproducible.

**Never introduce unseeded randomness.** If the numbers shift between runs, every prior
screenshot and description silently becomes wrong.

The generator models a gentle upward enrollment trend with a COVID-era dip, then derives
faculty counts, student-faculty ratio, and tuition revenue *from* enrollment so the tables
stay internally consistent. Preserve that derivation — inventing these independently would
produce combinations that cannot occur (e.g. ratios that contradict the headcount).

### Tables

| File | Grain | Contents |
|---|---|---|
| `data/metrics.csv` | One row per (year, department) | Enrollment, admissions funnel, faculty, revenue |
| `data/students.csv` | Student-level sample | ~3% of total enrollment per department-year |
| `data/courses.csv` | Course-section level | Year, term, course, capacity, fill rate, grades |

### Dimensions (hardcoded in `generate_data.py`)

- **Years:** 2015–2025 inclusive
- **Departments → majors:** Engineering (Computer Science, Mechanical, Electrical, Civil),
  Business (Finance, Marketing, Accounting, Management), Arts & Sciences (Biology,
  Psychology, History, Mathematics), Education (Elementary Ed, Special Ed, Curriculum),
  Nursing (Nursing BSN, Public Health), Law (JD Program, Legal Studies)
- **Class levels:** Freshman, Sophomore, Junior, Senior, Graduate
- **Residency:** In-State, Out-of-State, International
- **Terms:** Fall, Spring
- **Course levels:** 100–500 (500 = graduate)

Course codes are built from a `MAJOR_PREFIX` map (e.g. Computer Science → `CS-201`).

Changing any dimension requires regenerating all three CSVs — they are cross-consistent and
cannot be edited independently.

## UI Rules

### Layout
- **Six tabs** over one shared filter state: Enrollment, Academics, Courses, Admissions,
  Finance & Ops, Data.
- **Sidebar filters** apply across all tabs: year range, department, residency, gender, term.
- **KPI cards** at the top show headline metrics with year-over-year deltas.
- Filters must be accessible but not dominant. Charts get the majority of the space.

### Consistency
- A filter set in the sidebar must affect every tab that can honor it. Never let a tab
  silently ignore the active filter — that is the fastest way to make the dashboard lie.
- Every chart needs a plain-English title. Format dollars with thousands separators and `$`.
- Institution/department names in full, not abbreviations, in legends and tooltips.

## What NOT to Do

- Do not present synthetic figures as real institutional data anywhere
- Do not remove the synthetic-data disclaimer from the README or the app
- Do not introduce unseeded randomness into `generate_data.py`
- Do not edit the generated CSVs by hand — regenerate them instead
- Do not break the enrollment → faculty → revenue derivation chain
- Do not add a database or backend
- Do not add authentication or login
- Do not let a tab ignore the active sidebar filters
- Do not over-engineer — this is a prototype

## Deployment & Hosting

**Status: not publicly hosted. Runs locally.**

- **Repo:** https://github.com/anfelder613/university-dashboard — public.

This dashboard **cannot be hosted on GitHub Pages.** Pages serves static files only; this is
a Streamlit app and needs a running Python process. Do not add a Pages workflow here.

Unlike the tuition dashboard, this one has **no database** — the data is flat CSVs generated
at first run. It is therefore straightforward to publish on **Streamlit Community Cloud**
(free): point it at this repo and `app.py`, with no secrets or external services required.
That has not been set up, but nothing blocks it.
